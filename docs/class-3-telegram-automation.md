# Class 3 - Telegram Automation

## Overview

Class 3 focused on turning the n8n chatbot into a real Telegram bot.

Until this point, the assistant worked inside the n8n test chat. In this class, the workflow was adapted to receive and answer messages directly through Telegram.

---

## Objective

The objective was to create a functional chatbot interface using Telegram.

The final flow became:

```text
Telegram user
      |
      v
Telegram Trigger
      |
      v
AI Agent
      |
      v
Telegram Send Message
```

The AI Agent kept the same tools from the previous classes:

- Cohere Chat Model;
- Simple Memory;
- MySQL Tool;
- Simple Vector Store;
- Cohere Embeddings.

---

## Creating the Telegram Bot

The bot was created using BotFather, the official Telegram bot used to create and manage other bots.

The process included:

1. Starting a conversation with BotFather;
2. Using the `/newbot` command;
3. Defining the bot display name;
4. Defining a unique username ending in `bot`;
5. Receiving the Telegram Bot API token.

The token was then used as a private credential inside n8n.

---

## Telegram Trigger

The previous chat trigger was replaced by a Telegram Trigger.

The Telegram Trigger listens for new messages sent to the bot.

When a user sends a message, the trigger receives structured data such as:

```text
message.text
message.chat.id
message.from.id
message.from.first_name
```

The most important fields for this project were:

- `message.text`: the text written by the user;
- `message.chat.id`: the chat identifier used to send the response back.

---

## AI Agent Input

The AI Agent was configured to receive the Telegram message text as input.

The prompt was defined using:

```text
message.text
```

This change was necessary because the workflow no longer received messages from the internal n8n chat.

---

## Memory Session ID

The Simple Memory node originally depended on the internal chat trigger to identify the session.

After switching to Telegram, a new session identifier was needed.

The Telegram `chat.id` was used as the session ID.

This allows each Telegram conversation to have its own memory.

Example:

```text
Chat ID 1001 -> conversation memory for user A
Chat ID 2002 -> conversation memory for user B
```

---

## Sending Messages Back to Telegram

Receiving a message and sending a response are two different steps.

The Telegram Trigger receives the message, but another Telegram node is required to send the answer.

The final response node was configured with:

- Chat ID: the original Telegram `chat.id`;
- Text: the output generated by the AI Agent.

---

## Publishing the Workflow

During testing, the workflow had to be executed manually.

To make the bot work continuously, the workflow needed to be published or activated.

After publishing, the Telegram webhook could receive messages without manually executing the workflow each time.

---

## Final Test

The final test confirmed that the bot could:

- Receive a Telegram message;
- Ask for the employee name;
- Keep the name in memory;
- Understand a follow-up question;
- Query MySQL;
- Return the vacation balance through Telegram.

Example:

```text
User:
Maria Souza

User:
I would like to know about my vacation balance.

HR Buddy:
According to our records, you have 5 vacation days available.
```

## Result

At the end of Class 3, the project became a functional AI assistant connected to a real communication channel.

The assistant could:

- Receive Telegram messages;
- Use an AI Agent to process requests;
- Access general HR policies through RAG;
- Query employee data from MySQL;
- Keep conversation context;
- Send responses back to Telegram automatically.
